# Changelog

Every version is a tag on this repository. The build tag on the title screen (`BUILD 0.2.0`) is
this file's top entry — if they disagree, the running build is not the one you released.

## 0.2.0 — 2026-11-10

### Added

- **A support block** in the README and at the foot of the landing page: UPI, Ko-fi, PayPal, the
  author's books, the project index and the email address. The game never asked.
- **`VERSION`** at the repository root, so the release tag and the running build have one source.
- **This changelog.** Release history lived in `RELEASE_AUDIT.md`, which is a record of what was
  checked, not of what shipped.

### Fixed

- **Two of the four test suites had been failing on a missing file.** `play/tests/sw.test.js` and
  `play/tests/smoke.test.js` read `play/index.html`, which has not existed since the page moved to
  `docs/play/` — so the service-worker scope checks and the 82 feature checks never ran. They now
  find the page wherever it is, and both pass.
- The build tag moves with the version: `BUILD 0.1.6` → `BUILD 0.2.0`, in `play/game.js` and in
  both minified copies, regenerated by `node play/tools/minify.js`.

## 0.1.6 — 2026-10-31

Cache-correctness pass: the shell worker became network-first so a released build can never be
masked by a cached copy, `index.html` requests its assets with a version query, the page calls
`registration.update()` on load, and the title screen began printing a build tag.

## 0.1.5 and earlier

See `RELEASE_AUDIT.md` for the widescreen, menu and high-DPI pass and the measured frame times.
